# 学涯集市 · 高校学习资料交易平台

> 让每一份认真整理的笔记，都能被需要它的同学看见。

学涯集市是面向高校学生的学习资料交易平台，聚焦考研真题、期末复习、课堂笔记、课件讲义等真实需求场景。平台以「院校 / 学科 / 老师」三维筛选为基础，通过官方价格标准库与智能推荐定价降低交易摩擦，以试读预览、实名认证与自动交付保障交易安全，并提供 7×24 小时 AI 智能客服、平台工单与统一卖家沟通入口，形成从上传、审核、购买、交付到售后的完整闭环。

本项目参加 **TRAE AI 全国大学生创造力大赛 · 校园生活赛道**。

**交付形态：网页端应用（Web App）**，浏览器访问即可使用，同时提供单文件离线演示页，不依赖桌面客户端。正式版评估、优化记录与上线清单见 [docs/production-readiness.md](docs/production-readiness.md)；竞赛竞争力评估与迭代路线见 [docs/competition-readiness.md](docs/competition-readiness.md)；提交前行动方案见 [docs/award-sprint-plan.md](docs/award-sprint-plan.md)。

## 二、核心功能

### 1. 三维分类筛选
- 院校 / 学科 / 老师三个维度自由组合筛选，支持关键词搜索、价格区间与排序。
- 筛选项带真实数量统计，无结果时给出替代建议。
- 认证用户默认进入本校专区，可一键切换「全部院校」或手动查看其他高校。
- 顶部「资源库」提供院校、学科、教师三个模块的独立全局搜索，支持模糊匹配与实时返回，可直接跳转资料市场。

### 2. 智能定价体系
- 基于院校公开资料维护官方价格标准库，支持 院校 + 学科 + 类型 精确匹配。
- 匹配优先级：精确组合 → 院校 + 类型 → 学科 + 类型 → 全平台类型参考价。
- 卖家上传时自动展示推荐价、可调区间与匹配依据，可一键采用或手动调整。
- 管理后台支持标准库增删改与单份资料人工调价，调价说明同步展示给卖家。

### 3. 自动交易与交付
- 支付成功后立即写入订单并开放完整文件权限，无需人工发放。
- 买家可在「我的订单」中重复下载；订单支持评价、退款申请。
- 支持微信、支付宝、银行卡三种外部支付方式，统一支付弹窗选择渠道。
- 回调统一验签、防重放、金额校验与幂等落账；超时支付单自动关闭，卖家收益 90% 结算，金额以「分」存储。
- 银行卡转账在真实环境由管理员在后台核对到账后「确认到账」，确认后订单完成并生成结算账单。

### 4. 资料试读预览
- 所有上架资料自动生成前 10%—20% 的试读片段。
- 试读区禁止选中、复制、右键与拖拽，并叠加平台水印。
- 购买前明确提示试读比例、字数与「不可复制下载」规则。

### 5. 客服与统一沟通
- AI 智能客服：7×24 小时全天候在线，免登录即可咨询，自动实时解答认证、支付、下载、退款、上传审核、定价、砍价与资源库使用等问题。
- 平台官方客服：处理 bug 报错、功能建议、交易投诉、账号认证等问题，工单支持状态流转与未读提醒。
- 卖家沟通：资料详情页、店铺主页、求购广场统一使用「联系卖家」入口，消息进入同一个会话窗口。
- 会话保留咨询场景分类（资料咨询 / 价格与优惠 / 交付与下载 / 售后问题 / 自由沟通）与场景化快捷回复，同时兼容自由输入。
- 消息、已读未读与历史记录统一存储；历史卖家咨询工单在启动时自动幂等迁移，避免重复入口与记录丢失。
- 暂不提供客服热线入口；人工客服暂未设置固定服务时间，后续通过公告配置，处理进展通过工单与站内消息同步。

### 6. 用户身份与权限
- 实名 + 高校学生双重认证：选择院校、填写真实姓名与学号，管理员审核。
- 未认证用户仅可浏览公开内容；购买、上传、发布求购均被服务端拦截。
- 认证通过后默认进入本校专区，认证院校锁定，变更需通过客服工单。

### 7. 平台基础能力
- 资料上传与自动试读生成、内容自动审核、后台审核、上下架、举报处理。
- 求购广场、收藏、评价、统一卖家沟通、公告、卖家中心与数据看板。
- 管理后台：概览、资料审核、内容审核、认证审核、客服工单、价格标准库、砍价活动、用户、举报、财务、支付对账、公告十二大模块。

### 8. 支付方式与对账
- 标准化微信、支付宝、银行卡三种外部支付方式，统一限额、时效与结算说明；平台不提供充值与提现。
- 支付流程：下单 → 扫码 / 转账 → 异步回调 → 订单完成，前端弹窗支持渠道切换、倒计时与状态轮询。
- 回调安全：HMAC-SHA256 验签、±5 分钟时间戳容差、金额校验与幂等落账。
- 后台「支付对账」按日汇总各渠道流水，并检测「已支付未完成订单」等异常。详见 [docs/payments.md](docs/payments.md)。

### 9. 内容自动审核
- 资料提交与修改时同步执行多维度检测，覆盖涉政、涉恐、涉黄、涉赌、涉毒、暴力诈骗、违禁物品与侵权盗版。
- 命中直接拦截规则的内容不写文件、不入库，返回明确合规提示；疑似内容正常提交并转人工复核，避免误杀。
- 分级阈值、规则库与单次扫描长度均可在后台动态调整，规则增删改即时生效，无需重启。
- 每次检测写入审核日志，记录结果、命中规则、处理状态与耗时，人工复核结果自动回写，支持筛选与追溯。
- 检测异常时降级为人工复核而非放行，规则读取失败回退内置规则，避免单点故障中断审核。详见 [docs/content-audit.md](docs/content-audit.md)。

### 10. 好友砍价
- 用户在资料详情页发起砍价，生成专属砍价单并分享链接；好友登录后即可助力，每次随机砍掉一部分差价。
- 活动规则：固定有效期、初始价、目标底价、单个用户可砍次数、单张砍价单最大助力人数；最后一位助力好友直接砍到底价。
- 服务端快照：发起时把价格与规则写入砍价单，之后修改活动不影响已创建砍价单；所有金额由服务端计算，前端传价一律忽略。
- 助力幂等：`砍价单 + 用户 + requestId` 唯一约束，重复点击或网络重试不会重复砍价；并发请求使用事务与乐观更新保证价格一致。
- 前端展示进度条、剩余时间、剩余助力次数、助力用户列表与一键分享；砍到底价后发起人可按专享价直接购买，复用现有支付流程。
- 管理后台支持活动创建、规则校验、上下架、删除与运营数据统计。详见 [docs/bargain.md](docs/bargain.md)。

### 11. 全国院校与专业资源库
- 完整收录教育部《全国高等学校名单（2026）》**3196 所院校**（普通高校 2952 所、成人高校 244 所，覆盖 31 个省级行政区），以及《普通高等学校本科专业目录（2026年）》**883 个本科专业**（13 个学科门类、92 个专业类）。
- 院校字段包含官方标识码（10 位）、主管部门、办学层次、办学类型、办学性质与数据来源；专业字段包含专业代码、学科门类、专业类、学位说明、特设 / 国家控制布点标记。
- 院校、专业、学科、教师四个模块各自提供独立全局搜索：院校支持名称 / 标识码 / 省份 / 层次 / 办学类型，专业支持名称 / 代码 / 门类 / 专业类，学科支持名称 / 门类，教师支持姓名 / 院校 / 学科 / 职称的模糊匹配与多关键词组合查询。
- 搜索接口在 SQLite 索引上执行并在服务端完成相关度排序，实测单次响应通常在 10 ms 内，稳定低于 1 秒；结果可直接跳转资料市场查看对应资料。
- 资源库在服务启动时按官方名单全量校准：自动补齐官方字段、删除不在官方名单内的历史条目，重复启动不会产生重复数据；不依赖外部网络。
- 中等职业学校暂无教育部全国统一名单（省级名单口径不一），为避免引入非官方数据，本资源库不纳入中职条目，已在 `server/data/catalog-manifest.json` 的 `coverage` 中明确说明。

### 12. 7×24 小时 AI 智能客服
- 客服中心新增 AI 智能客服，全天候在线、免登录即可咨询，自动实时回复认证、支付、下载、退款、上传审核、定价、砍价与资源库使用等问题。
- 服务端基于意图识别与本地知识库匹配，支持追问建议与未命中兜底；兜底时引导提交人工工单，避免咨询无响应。
- 暂不提供客服热线入口；人工客服暂未设置固定服务时间，后续通过公告配置，工单处理进展通过站内消息同步。

### 13. AI 学习规划与打卡
- 选择期末冲刺、考研备考、竞赛考证、论文写作、语言提升五类目标，结合学科、院校、已购与收藏生成学习计划。
- 本地可解释规则引擎：按学科匹配、同校、目标场景、评分、下载热度、价格与购买状态多因子排序，每份推荐都给出命中理由，结果可复现。
- 输出资料覆盖率、已具备与待补齐分类、逐日主任务与间隔复习、执行建议；生成耗时稳定低于 1 秒。
- 登录后可保存计划、在「我的计划」中继续、逐项打卡并自动统计进度；重复打卡幂等，计划与打卡记录按用户隔离。
- 不采集资料内容、不上传个人文件，也不依赖外部大模型，适合无外网或低成本部署场景。

### 14. 生产化与内测准入（v1.1.0）
- `SEED_DEMO` 控制演示数据：生产模式默认不写入演示账号与订单，启动日志不输出演示密码。
- `INVITE_CODES` 邀请码准入，支持按次数限制；注册接口与前端注册弹窗同步校验。
- `FEATURE_*` 功能开关：注册、上传、支付、规划、砍价、AI 客服、工单可独立关闭，前端入口自动隐藏。
- `TRUST_PROXY` 控制是否信任 `X-Forwarded-For`；未开启时伪造 IP 无法绕过限流。
- `ADMIN_IP_ALLOWLIST` 限制后台来源网络，支持单个 IP 与 CIDR（逗号分隔）；未配置时默认仅放行本机与私网。
- `ADMIN_LOGIN_PATH` 管理员专属登录入口路径，默认 `/ops-login`；该页面独立且标记 `noindex`，不参与站内导航。
- `ADMIN_MFA_SECRET` 管理员 TOTP 绑定密钥（base32）；未配置时首次登录会在密码校验通过后引导一次性绑定验证器。
- `ADMIN_ALERT_WEBHOOK` 异常登录告警 Webhook 地址；配置后锁定、新设备、新网络等告警会异步 POST 到该地址。
- 上传增加文件魔数与 UTF-8 校验；支持 `SIGTERM` 优雅退出，适配容器与 systemd。

### 15. 收益结算与正式版加固
- 每笔支付成功后自动生成卖家结算账单：订单金额、10% 平台服务费、结算金额、结算状态一目了然。
- 默认 T+1 自动结算，服务启动与每 5 分钟执行到期结算；升级时为历史订单自动补建账单。
- 订单退款通过后，支付单标记「已退款」、结算记录自动取消、卖家收益同步扣回。
- 卖家中心、个人中心「账单与收益」、后台「支付对账」三处均可查看结算数据。
- 安全加固：登录 / 注册 / AI 客服 / 支付模拟限流、CSP 与安全响应头、32MB 请求体上限、8—72 位字母数字密码策略。
- 健康检查返回数据库状态与支付模式，异常时返回 503，便于探针与部署平台监控。

## 三、技术架构

**零运行时依赖**：不使用 npm 包、不使用前端框架、不使用构建工具。

| 层 | 技术 | 说明 |
| --- | --- | --- |
| 运行时 | Node.js ≥ 22.5 | 原生 `node:http`、`node:sqlite`、`node:crypto` |
| 数据库 | SQLite（单文件） | WAL 模式，启动时幂等建表与补列迁移 |
| 鉴权 | HMAC-SHA256 Bearer Token | 密钥首次启动生成并保存在 `data/secret.key` |
| 前端 | 原生 ES Modules + Hash 路由 | 无打包步骤，浏览器直接加载 |
| 样式 | 手写 CSS 设计系统 | 设计令牌、组件类、响应式 |
| 文件 | 本地磁盘 `data/uploads` | 预留对象存储替换接口 |

```
浏览器 (原生 SPA)
      │  fetch / JSON
      ▼
node:http 路由 ── 鉴权中间件 ── 业务 API
      │
      ├── SQLite (data/xueya.db)
      └── 文件存储 (data/uploads)
```

更完整的数据模型、API 清单与扩展方案见 [docs/architecture.md](docs/architecture.md)。

## 四、快速开始

环境要求：Node.js ≥ 22.5（推荐 24 LTS 或更高）。

```bash
# 1. 启动服务（首次启动自动建库并写入演示数据）
npm start

# 2. 打开浏览器
# http://localhost:3300
# 离线演示（无需登录）：http://localhost:3300/demo.html
```

无需 `npm install`。

### 多台电脑共同使用（局域网）

服务默认监听 `0.0.0.0`，启动后终端会打印局域网地址（如 `http://192.168.1.23:3300`），同一网络下的其他电脑用浏览器打开该地址即可，无需安装任何客户端。其他电脑打不开时，用管理员权限执行一次 `npm run firewall:open` 放行端口。

详细步骤、数据备份、公网部署与故障排查见 [docs/network-access.md](docs/network-access.md)。

支付默认运行在 `PAYMENT_MODE=mock`，可直接在支付弹窗中模拟支付成功 / 失败。接入真实渠道时配置：

```bash
PAYMENT_MODE=live \
WECHAT_APP_ID=... WECHAT_MCH_ID=... WECHAT_API_V3_KEY=... \
ALIPAY_APP_ID=... ALIPAY_APP_SECRET=... \
BANK_MCH_ID=... BANK_MERCHANT_KEY=... \
npm start
```

完整参数、回调协议与对账口径见 [docs/payments.md](docs/payments.md)。

## 七、商业化路径

平台采用「交易抽成 + 增值服务 + 机构 SaaS」的三层收入结构，按「单校试点 → 区域高校联盟 → 全国多校 SaaS」三阶段推进。详细的市场分析、单位经济模型、冷启动方案与合规风险见 [docs/business-plan.md](docs/business-plan.md)。

- **阶段一（0—6 个月）**：1—2 所高校试点，验证供需密度与复购，抽成 10%。
- **阶段二（6—18 个月）**：区域高校联盟，上线会员包、置顶推广、机构认证服务。
- **阶段三（18 个月以上）**：向院系 / 学生会 / 教育机构输出 SaaS 与内容合作。

## 九、数据与合规说明

- 演示数据均为虚构，不包含真实学生个人信息。
- 实名信息仅用于校园身份核验，正式运营需接入加密存储、最小化采集与授权审计。
- 平台定位为学习资料分享与交易撮合，禁止上传教材扫描件、付费课程、盗版资源与含个人隐私的内容。
- 生产环境需补齐支付资质、内容版权审核机制与个人信息保护合规流程。
