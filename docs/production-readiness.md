# 正式版评估与上线说明

本文档回答两件事：

1. 参赛项目以什么形式交付；
2. 当前版本距离「可实际落地使用」还差什么、本轮改了什么、上线前还要补什么。

---

## 一、交付形式结论：Web 应用

**本项目交付为网页端应用（Web App），不是桌面端软件。**

- 形态：响应式单页应用（原生 ES Modules + Hash 路由） + Node.js 服务端 + SQLite 单文件数据库。
- 访问方式：浏览器打开域名即可使用，桌面端与移动端共用同一套页面，无需安装客户端。
- 离线演示：`public/demo.html` 为单文件可体验页面，可直接双击或通过 `/demo.html` 打开，用于评委快速体验，不依赖服务端。
- 部署方式：本地 `npm start`、Docker、云主机或托管平台均可，详见 [deployment.md](deployment.md)。
- 选择 Web 而非桌面端的原因：
  - 支付回调、实名认证审核、后台运营都依赖服务端与公网 HTTPS 地址；
  - 参赛与评审只需一个链接，跨平台、零安装；
  - 后续接入小程序 / 公众号时，服务端与数据库可直接复用。

## 二、优化空间评估

评估基于当前代码与 322 项自动化测试结果，按「现状 → 问题 → 本轮处理」列出。

### 1. 功能完整性

| 现状 | 问题 | 本轮处理 |
| --- | --- | --- |
| 注册、登录、实名认证、审核闭环完整 | 密码仅要求 6 位，弱口令可注册 | 提升为 8—72 位且必须同时包含字母和数字，注册与改密同步生效 |
| 上传、机审、人工审核、下载完整 | 20MB 文件经 Base64 编码后约 26.7MB，超过原 24MB 请求体上限，大文件会被 413 拦截 | 请求体上限提升至 32MB，与 20MB 文件限制匹配 |
| 微信 / 支付宝 / 银行卡支付与回调验签完整 | 银行卡转账在真实环境无法自动回调，缺少人工到账确认入口 | 后台新增「确认到账」，仅对银行卡待支付单展示，幂等处理并生成结算 |
| 卖家收益只累加余额，缺少账单 | 无法核对每笔订单的服务费、结算金额与结算状态 | 新增结算账本 `settlements`，支付成功即生成账单，支持 T+1 自动结算、退款取消、后台台账与历史订单补建 |
| 退款只改订单与余额 | 支付流水仍显示已支付，结算记录未联动 | 退款通过后支付单标记「已退款」、结算记录置为「已取消」、卖家收益扣回 |
| 缺少找回密码、邮箱验证 | 无邮件服务时无法安全实现 | 明确列为上线前依赖项，不在演示版伪造流程 |

### 2. 用户体验

| 问题 | 本轮处理 |
| --- | --- |
| 卖家看不到「待结算 / 已结算 / 服务费」拆分 | 卖家中心新增「收益结算」面板与最近结算明细 |
| 个人中心只有支付记录，没有收益账单 | 「账单与收益」新增待结算、已结算卡片与结算记录 |
| 后台只能看支付流水，看不到卖家结算 | 「支付对账」新增收益结算台账与汇总 |
| 密码规则变更后提示不一致 | 注册、改密、登录提示统一更新 |
| 大文件上传失败原因不直观 | 服务端仍返回明确提示，前端保留 20MB 前置校验 |

### 3. 性能表现

| 现状 | 问题 | 处理 |
| --- | --- | --- |
| 列表、搜索、AI 客服响应均在毫秒级 | 订单、资料、评价、举报等高频查询缺少组合索引 | 新增 9 个业务索引与 2 个学习计划索引，覆盖买家订单、卖家订单、资料归属、评价、举报、结算、计划与打卡 |
| 结算需要按状态与到期时间扫描 | 无索引时随订单量增长变慢 | `settlements(status, settle_due)` 与 `settlements(seller_id, status, created_at)` |
| 大响应与静态文本传输体积偏大 | 移动端首屏与接口响应可进一步压缩 | JSON > 1KB 与可压缩静态资源按 `Accept-Encoding` 协商 gzip，并返回 `Vary` |
| 学习计划按用户查询 | 计划列表与打卡记录随使用增长 | `study_plans(user_id, created_at)`，打卡记录以 `(plan_id, task_key)` 主键保证幂等 |
| 静态资源无缓存策略 | 迭代期希望即时生效 | 保持 `no-cache`，生产可交给 Nginx/CDN 处理 |
| 健康检查只返回进程状态 | 无法判断数据库是否可用 | 健康检查增加数据库探测与支付模式，异常返回 503 |

### 4. 安全性

| 问题 | 本轮处理 |
| --- | --- |
| 登录、注册、AI 客服、支付模拟可被高频尝试 | 新增单进程限流：登录 20 次/分钟、注册 10 次/10 分钟、AI 60 次/分钟、支付模拟 30 次/分钟，超限返回 429 + `Retry-After` |
| 页面缺少内容安全策略 | 非演示页统一下发 CSP（`script-src 'self'`、`frame-ancestors 'none'` 等），`demo.html` 因含内联脚本单独放行 |
| 上传体积与接口滥用 | 请求体上限 32MB，文件仍限制 20MB，超限明确拒绝 |
| 权限边界 | 上传、下载、购买、退款、后台结算均有服务端守卫；本轮补充「普通用户不可访问结算后台」测试 |
| 支付回调 | 保留 HMAC-SHA256 验签、±5 分钟时间戳、金额校验、渠道校验与幂等落账 |

### 5. 代码架构

| 现状 | 评价 | 处理 |
| --- | --- | --- |
| 零 npm 依赖，`server/*.js` 按领域拆分 | 边界清晰、易审计，适合赛事与中小规模部署 | 新增 `settlements.js`（账本）、`api-settlements.js`（接口）、`rate-limit.js`（限流），不引入框架 |
| 数据库启动时幂等建表与补列 | 升级不需要手工迁移 | 新表与索引使用 `IF NOT EXISTS`，历史订单启动时自动补建结算记录 |
| 支付通道抽象 | mock 完整可跑，live 仅完成签名与回调骨架 | 真实商户接入需补充渠道下单与证书，已在下方「上线前依赖」列明 |
| 单进程内存限流 | 多实例部署会失效 | 文档标注：多实例需替换为 Redis |

### 6. 可运维性

- `/api/health` 返回服务、数据库、支付模式与运行时长，可直接接入探针。
- 结算任务每 5 分钟执行一次到期结算，进程重启后由查询与启动补建自愈。
- 退款、结算、支付状态均可在后台追溯。
- 仍缺少集中日志、告警、备份与审计导出，列入上线清单。

## 三、本轮已落地的核心链路

### 1. 注册、登录与身份验证

1. 注册：用户名 / 邮箱唯一，密码 8—72 位且包含字母和数字，返回 Bearer Token。
2. 登录：账号或邮箱 + 密码，错误统一提示，连续失败触发限流。
3. 实名认证：真实姓名 + 院校白名单 + 学号格式校验，提交后进入待审核。
4. 管理员审核：通过后 `verifyStatus=verified`，院校锁定；未认证用户无法上传、购买、发布求购。

### 2. 资料上传与下载

1. 仅认证用户可上传，支持 PDF / Word / PPT / Excel / ZIP / 图片 / 文本，单文件 ≤ 20MB。
2. 上传即触发内容自动审核，命中拦截规则不入库，疑似内容转人工复核。
3. 管理员审核通过后上架；试读片段默认 10%—20%，禁止复制与下载。
4. 购买成功后开放下载权限，支持重复下载；卖家与管理员可直接下载。

### 3. 支付链路

1. 选择资料 → 选择微信 / 支付宝 / 银行卡 → 创建待支付订单与支付单。
2. 微信 / 支付宝展示扫码参数，银行卡展示转账备注；支付单 15 分钟有效。
3. 回调统一验签、校验金额与渠道、防重放、幂等落账；超时自动关闭订单。
4. 演示模式可模拟成功 / 失败；生产模式银行卡转账由管理员「确认到账」。
5. 平台不提供充值、提现与余额支付，资金只在微信 / 支付宝 / 银行卡之间流转。

### 4. 收益与结算

1. 订单支付成功：订单完成，卖家余额增加「订单金额 − 10% 服务费」，同时生成结算记录。
2. 结算状态：`pending`（待结算）→ `settled`（已结算），默认 T+1；可用 `SETTLEMENT_DELAY_HOURS` 调整。
3. 到期结算：服务每 5 分钟执行一次，卖家/后台查询时也会即时结算到期记录。
4. 退款：管理员通过后，支付单标记「已退款」、结算记录「已取消」、卖家收益扣回。
5. 历史数据：升级启动时为既有已完成订单补建结算记录，账单不断档。
6. 展示入口：卖家中心、个人中心「账单与收益」、后台「支付对账」。

## 五、上线前仍需补齐的依赖

以下事项不影响当前演示与评审，但正式对外运营必须完成：

1. **真实支付商户**：微信 / 支付宝商户号、API 证书与密钥；接入渠道下单 SDK 与退款接口；HTTPS 公网域名。
2. **账号体系**：邮箱或短信验证码、找回密码、登录设备管理、Token 主动失效。
3. **文件存储**：对象存储 + CDN，替代本地磁盘；病毒扫描与内容安全增强。
4. **多实例部署**：限流、会话、结算任务改为 Redis / 数据库锁；定时任务独立进程。
5. **合规**：ICP 备案、公安备案、隐私政策与用户协议、个人信息最小化与授权审计、论文范文类目合规（见 [thesis-trading-compliance.md](thesis-trading-compliance.md)）。
6. **可观测性**：结构化日志、错误告警、数据库备份与恢复演练、财务对账导出。
7. **风控**：异常登录、批量注册、刷单、恶意退款识别。
