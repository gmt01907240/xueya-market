# 支付能力说明与生产接入清单

> 结论：**参赛不需要真实商户号**。演示环境使用受控的模拟支付，真实交易能力按生产标准实现并留有接入清单，这比勉强接入个人收款更合规、更可复现。

## 一、现在到底是什么状态

| 能力 | 当前状态 | 说明 |
| --- | --- | --- |
| 下单与订单状态机 | 已实现 | 待支付 → 已支付 → 已完成 / 退款中 / 已退款 |
| 支付回调与验签 | 已实现 | 渠道回调做签名校验、金额校验、订单归属校验、防重放 nonce |
| 幂等 | 已实现 | `Idempotency-Key` 同键同体复用响应，同键不同体返回 409 |
| 担保交易 | 已实现 | 买家付款进入平台待结算，确认完成后按 T+7 结算给卖家 |
| 复式记账 | 已实现 | 每笔支付、结算、退款都有借贷分录，可逐笔追溯 |
| 退款与冲正 | 已实现 | 退款生成反向分录；已结算订单退款时结算记录标记 `reversed` |
| 生产支付闸门 | 已实现 | `NODE_ENV=production` 且 `PAYMENT_MODE=mock` 时拒绝启动，避免“假支付上线” |
| 真实商户号 | **未接入** | 个人参赛者没有营业执照/商户资质，无法开通微信支付、支付宝商户 |
| 演示支付 | 已启用 | 支付弹窗明确标注“演示支付 · 不产生真实扣款”，可模拟成功与失败 |

演示环境（`DEPLOY_PROFILE=public-demo`）是唯一允许模拟支付的公网形态；生产形态必须配置真实渠道，否则启动即失败。这是有意的合规设计，不是缺口。

## 二、为什么个人做不到真实收款

- 微信支付、支付宝的商户号需要**营业执照或小微商户资质**，个人开发者无法以经营性用途开通。
- 个人收款码明确禁止用于经营性收款，用它收资料费存在合规与封号风险。
- 即使借到商户号，回调域名、证书、对账、退款权限、客服与争议处理也需要主体承担。

因此，“没有真实支付账户”是**主体资质问题，不是技术问题**。评委考察的是是否想清楚、是否按真实场景实现，而不是当场扣一笔真钱。

## 三、三种可选方案对比

| 方案 | 成本 | 合规 | 评委感知 | 建议 |
| --- | --- | --- | --- | --- |
| A. 保持模拟支付 + 生产接入清单 | 0 | 高 | 中高：能讲清边界与工程完成度 | **推荐** |
| B. 接入支付宝沙箱 | 1—2 天 | 高 | 中：可展示签名回调，但多数评委分不清沙箱与生产 | 可选，非必需 |
| C. 个人转账 + 人工确认 | 低 | 低：个人码经营收款有风险 | 低：显得原始，且售后争议大 | 不推荐 |

若坚持要“更接近真实”，优先选 B：支付宝开放平台的沙箱环境免费，可演示 RSA2 签名回调；但需要开发者账号与额外联调时间，收益主要是技术展示，不是评分必需项。

## 四、生产接入清单（写进材料即可）

1. **主体与资质**：营业执照或小微商户主体，完成微信/支付宝商户进件。
2. **商户参数**：`PAYMENT_MODE=live`，配置 `WECHAT_MCH_ID`、`WECHAT_API_V3_KEY`、`ALIPAY_APP_ID`、`ALIPAY_APP_SECRET` 等。
3. **证书与密钥**：API v3 密钥、商户私钥/平台公钥，按环境隔离，禁止入库。
4. **回调域名**：HTTPS 域名 + 备案，配置 `WECHAT_NOTIFY_URL` / `ALIPAY_NOTIFY_URL`，验签失败拒绝。
5. **对账**：按日拉取渠道账单，与 `payments`、`ledger`、`settlements` 三方核对，差异进工单。
6. **退款**：商户后台开通退款权限，退款金额不得超过原单，退款结果回写并冲正结算。
7. **合规**：支付页面展示价格、退款规则、客服入口；不诱导私下交易。
8. **演练**：沙箱或 1 分钱真实单跑通“支付成功、支付失败、重复回调、退款”四条链路。

## 五、评审话术（三句）

> 演示环境使用模拟支付，避免评审现场产生真实扣款，这一点在支付弹窗里有明确标注。
>
> 真实支付的技术链路已经按生产标准实现：回调验签、金额校验、幂等、担保结算、退款冲正和生产闸门；缺的只是商户资质。
>
> 个人参赛无法开通商户号，所以我们把“怎么接、接完怎么对账”写成了接入清单，而不是做一个看起来能收款、实际不可用的壳子。

## 六、没有真实支付时，试点怎么做

- 试点期间把参与资料设为免费或 0 元单，走完整“下单 → 交付 → 评价”流程。
- 重点采集不依赖支付的数据：计划生成率、次日打卡率、试读→下单转化、任务完成率。
- 反馈问题里明确问“如果这份资料 9.9 元，你会买吗”，得到支付意愿而不是真实流水。
- 材料中写“试点使用免费资料验证流程，付费转化以问卷意愿衡量”，不虚构交易额。

## 七、提交前检查

- [ ] 支付弹窗可见“演示支付 · 不产生真实扣款”
- [ ] 作品帖、视频字幕、答辩口径三处一致
- [ ] 不出现“已接入微信/支付宝收款”“真实交易额”等表述
- [ ] 生产闸门可演示：`NODE_ENV=production` + `PAYMENT_MODE=mock` 启动失败
- [ ] 接入清单已放入作品帖附录或仓库文档
