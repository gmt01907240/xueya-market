# 版本说明 · v1.1.0

发布日期：2026-11-20
版本类型：内测 / 公测候选（Release Candidate）
交付形态：Web 应用（Node ≥ 22.5，零 npm 依赖），附单文件离线演示页
测试结论：322 项自动化测试全部通过，0 阻塞性问题

---

## 1. 版本定位

v1.1.0 是在 v1.0.0 正式版能力基础上的**生产化加固版本**，重点不是新增业务功能，而是让项目具备真实用户内测所需的隔离、准入、开关、审计与回滚能力，同时补齐 AI 学习计划的保存与打卡闭环。

适用场景：

- 预发环境验收；
- 邀请制内测；
- 公测前灰度；
- 竞赛现场演示。

不适用于：未完成 ICP 备案、真实支付商户接入与等保评估的公网生产环境（见合规自检报告）。

## 2. 本版变更

### 2.1 生产安全与隔离

| 变更 | 说明 |
| --- | --- |
| 演示数据开关 | 新增 `SEED_DEMO`。生产模式默认不写入演示账号、演示订单；启动日志不再输出演示密码 |
| 反向代理信任 | 新增 `TRUST_PROXY`。未开启时忽略 `X-Forwarded-For`，防止伪造 IP 绕过限流 |
| 请求追踪 | 每个 API 请求生成 `X-Request-Id`，输出 JSON 访问日志（方法、路径、状态、耗时、IP、用户 ID） |
| 优雅退出 | 支持 `SIGTERM` / `SIGINT`，停止接收新请求、关闭空闲连接，超时强制退出，适配容器与 systemd |
| 后台来源限制 | 新增 `ADMIN_IP_ALLOWLIST`，非白名单来源访问 `/api/admin/*` 返回 403 |
| 上传内容校验 | 在扩展名与大小之外增加文件魔数校验（PDF/ZIP/OLE/PNG/JPG/RAR），文本文件校验 UTF-8 与二进制内容 |
| Nginx 体积上限 | 部署文档请求体上限由 25m 调整为 35m，避免 20MB 文件 Base64 后被代理层拦截 |

### 2.2 内测准入与功能开关

| 变更 | 说明 |
| --- | --- |
| 邀请码 | 新增 `INVITE_CODES`，格式 `CODE:次数,CODE2:次数`；注册校验邀请码并按次数扣减，大小写不敏感 |
| 功能开关 | 新增 `FEATURE_REGISTRATION`、`FEATURE_UPLOAD`、`FEATURE_PAYMENTS`、`FEATURE_PLAN`、`FEATURE_BARGAIN`、`FEATURE_AI_SUPPORT`、`FEATURE_TICKETS` |
| 前后端联动 | `/api/meta` 下发环境与开关；前端隐藏注册、上传、规划、砍价等入口，服务端仍做二次校验 |
| 邀请码前端 | 开启邀请码后，注册弹窗自动显示邀请码输入框；关闭注册时隐藏注册入口 |

### 2.3 AI 学习计划

| 变更 | 说明 |
| --- | --- |
| 计划保存 | 登录用户可保存生成结果，最多 20 份，按用户隔离 |
| 每日打卡 | 支持逐项勾选、取消，进度实时统计；重复打卡幂等 |
| 我的计划 | 展示目标、学科、天数、覆盖率、完成进度，可继续或删除 |
| 数据表 | 新增 `study_plans`、`study_plan_checks` 与对应索引 |

### 2.4 性能与稳定性

- JSON > 1KB 与可压缩静态资源按 `Accept-Encoding` 按需 gzip，返回 `Vary`。
- 新增订单、资料、评价、举报、结算、学习计划组合索引。
- 健康检查包含数据库探测，异常返回 503。
- 支付回调验签、时间戳防重放、金额/渠道校验、幂等落账保持既有能力。
- 结算 T+1、退款联动取消、银行卡人工确认保持既有能力。

### 2.5 多用户访问

| 变更 | 说明 |
| --- | --- |
| 监听所有网卡 | 新增 `HOST` 配置，默认 `0.0.0.0`，同一局域网的其他电脑可直接访问 |
| 局域网地址提示 | 启动横幅自动列出本机 IPv4 地址，形如 `http://192.168.1.23:3300`，无需手工查 IP |
| 端口冲突提示 | `EADDRINUSE` / `EACCES` 时输出可操作的提示，不再直接抛栈 |
| 防火墙放行脚本 | 新增 `npm run firewall:open`（`scripts/allow-firewall.ps1`），管理员权限下放行入站端口，支持 `-Port` 与 `-Remove` |
| 使用说明 | 新增 [network-access.md](./network-access.md)，覆盖架构、启动、防火墙、备份、故障排查与公网访问 |

使用方式：服务端执行 `npm start`，其他电脑浏览器打开终端打印的局域网地址即可，无需安装客户端。多用户共享同一份数据库与上传目录。

## 3. 升级步骤

1. 备份 `DATA_DIR`（数据库、上传文件、`secret.key`）。
2. 拉取 v1.1.0 代码，确认 `package.json` 版本为 `1.1.0`。
3. 按目标环境配置变量（见 4. 环境变量）。
4. 重启服务，确认 `/api/health` 返回 `version: 1.1.0` 且 `database: ok`。
5. 执行 `npm run test:release`、`npm test` 与核心业务套件。
6. 检查启动日志：生产环境应显示「演示数据：未启用（生产模式）」，且不出现演示密码。

数据库变更均为 `CREATE TABLE IF NOT EXISTS` 与新增索引，向前兼容，无需手工迁移；回滚代码即可继续使用旧表结构。

## 4. 环境变量

| 变量 | 默认 | 生产建议 | 说明 |
| --- | --- | --- | --- |
| `NODE_ENV` | development | production | 生产模式默认关闭演示数据 |
| `PORT` | 3300 | 3300 | 建议仅监听 127.0.0.1 |
| `DATA_DIR` | 项目 `data/` | 持久化卷 | 数据库、上传、密钥 |
| `SEED_DEMO` | 非生产为 true | false | 生产禁止演示账号 |
| `TRUST_PROXY` | false | true | 仅在 Nginx 后开启 |
| `INVITE_CODES` | 空 | 内测批次码 | `BETA-001:50,BETA-002:100` |
| `FEATURE_*` | 全部开启 | 按阶段 | `off`/`false`/`0` 关闭 |
| `ADMIN_IP_ALLOWLIST` | 空 | 办公网/VPN 出口 | 逗号分隔，留空不限制 |
| `RATE_LIMIT_*` | 代码默认 | 按流量调整 | 登录、注册、规划、支付模拟等 |
| `PAYMENT_MODE` | mock | live | 真实渠道需配齐商户参数 |
| `SETTLEMENT_DELAY_HOURS` | 24 | 24 | T+1 结算 |

完整清单见 [deployment.md](deployment.md)。

## 6. 已知限制

1. 默认支付模式仍为 `mock`；真实微信/支付宝/银行卡需配置商户参数并完成联调。
2. 单进程 + SQLite，适合内测与中小规模公测；写 QPS 持续超过 50 或数据库超过 2GB 时需迁移 PostgreSQL。
3. 暂无邮箱/短信找回密码、账号自助注销、未成年人年龄门槛，需在公测前补齐或提供人工流程。
4. 上传文件未接入第三方病毒扫描；当前为扩展名、大小、魔数、UTF-8 校验。
5. ICP 备案、等保评估、支付商户资质属于组织与外部资质事项，代码无法替代。
6. 监控为 JSON 日志 + 健康检查，未内置 Prometheus/Grafana；生产建议接入外部采集。

## 7. 回滚说明

- 代码回滚：切回上一版发布目录或 `git` tag，重启服务。
- 数据回滚：仅在确认数据损坏时执行；先停止服务，再从最近备份恢复 `DATA_DIR`。
- 本版数据库变更向前兼容，回滚代码无需删除新表。
- 回滚后必须重新执行 `/api/health` 与冒烟测试，并公告影响范围。
