# 内容自动审核机制

学涯集市对用户提交的资料执行「提交即检测」。检测在写文件与入库之前同步完成，命中直接拦截规则的内容不会落库、不会生成上传文件，也不会出现在任何对外页面；疑似内容正常入库并转入人工复核通道。审核全过程留痕，可在管理后台查询与追溯。

---

## 一、检测能力

### 1. 多维度规则体系

规则按违规分类与处理等级两个维度组织：

| 分类 | 覆盖内容 | 示例规则类型 |
| --- | --- | --- |
| 涉政 | 危害国家安全、分裂势力、非法组织、攻击性政治表述 | 正则组合语义 + 关键词 |
| 涉恐 | 恐怖组织、极端主义宣传、爆炸物制作、恐怖招募 | 正则 + 关键词 |
| 涉黄 | 色情交易、低俗内容、未成年人色情 | 正则 + 关键词 |
| 涉赌 | 赌博平台推广、引导下注开户、博彩代理 | 正则 + 关键词 |
| 涉毒 | 制毒贩毒、毒品交易、吸毒工具 | 正则 + 关键词 |
| 暴力诈骗 | 刷单返利、杀猪盘、洗钱跑分、暴力犯罪教程、自伤自杀 | 正则 + 关键词 |
| 违禁物品 | 枪支弹药、管制刀具、窃听设备、迷药 | 正则 + 关键词 |
| 侵权盗版 | 盗版资源传播、代考代写等学术黑产 | 正则 + 关键词 |

每类规则内置多条规则，覆盖「明确交易/教程」与「学术讨论可能提及」两种语境。内置规则随服务启动幂等写入 `audit_rules` 表，管理员可新增、编辑、停用或删除，也可直接调整权重。

### 2. 匹配与规避对抗

- **文本归一化**：NFKC 归一、大小写统一、移除零宽字符。
- **紧凑匹配**：关键词匹配前去除空格、标点、符号，防止「赌 博」「赌-博」等简单拆分规避。
- **正则组合**：用「行为动词 + 对象」的组合模式识别真实违法意图，如「出售/购买/制作 + 毒品」，降低单个敏感词造成的误判。
- **多字段拼接**：标题、介绍、分类、学科、老师、课程、标签、文件名与文件正文（文本类文件）统一检测。

### 3. 分级判定

| 判定 | 条件 | 处理 |
| --- | --- | --- |
| `block` | 命中任意「直接拦截」规则，或累计权重 ≥ 拦截阈值 | 拒绝提交（HTTP 422），返回明确合规提示；不写文件、不入库 |
| `review` | 命中「人工复核」规则，或累计权重 ≥ 复核阈值 | 正常提交，资料标记 `audit_status = review`，进入人工复核并优先展示给管理员 |
| `pass` | 未达到以上条件 | 正常提交，标记机审通过，仍按原有流程进入人工审核 |
| `error` | 规则读取或检测过程异常 | 降级为人工复核，绝不自动放行 |

默认阈值：复核 30 分、拦截 80 分。阈值、单次扫描字符数（默认 200000）与审核开关均可在管理后台动态调整，保存后即时生效。

## 二、提交审核流程

```
用户提交资料
   │
   ├── 解码文件 → 抽取正文（文本类文件最多 120KB）
   ├── 拼接元数据与正文 → 同步检测（毫秒级）
   │
   ├── block → 写审核日志（target_id 为空）→ 422 + 合规提示
   ├── review / error → 写文件、入库（status=pending）→ 写日志 → 转人工复核
   └── pass → 写文件、入库（status=pending）→ 写日志 → 正常人工审核
```

资料修改（PATCH）执行同样的检测；若修改后命中拦截规则，则保持原内容不变并拒绝本次修改。

---

## 三、规则动态更新

- 规则持久化在 `audit_rules` 表，服务启动时加载到内存缓存。
- 缓存默认 5 秒过期，管理后台的新增、修改、停用、删除会立即失效缓存，无需重启。
- 也支持手动「刷新缓存」。
- 规则支持导入式维护：直接更新数据库后调用刷新接口即可生效。

### 规则字段

| 字段 | 说明 |
| --- | --- |
| `code` | 唯一编号，3—40 位大写字母、数字、下划线或短横线 |
| `category` | 违规分类 |
| `level` | `block`（直接拦截）/ `review`（人工复核）/ `watch`（关注项） |
| `weight` | 1—100，多个关注项累计可触发复核 |
| `match_type` | `keyword`（`|` 分隔多关键词）或 `regex` |
| `pattern` | 匹配表达式 |
| `tip` | 命中说明，展示给管理员与提交人 |
| `active` | 是否启用 |

## 四、审核日志与审计

每次提交、修改均写入 `audit_logs`，包含：

- 检测结果（`pass` / `review` / `block` / `error`）、累计分数、处理状态；
- 命中规则编号、分类、等级、说明与片段（不存储完整敏感正文）；
- 文本 SHA-256 摘要，便于比对但不泄露内容；
- 提交人、资料 ID、动作（提交 / 修改）、检测耗时、时间；
- 人工复核结果回写：管理员通过 / 驳回 / 下架后，最近一条日志更新为 `manual_approved` / `manual_rejected` 并记录原因。

管理后台「内容审核 → 审核日志」支持按结果筛选、分页查看；也提供规则命中次数统计，便于持续优化规则。

## 五、稳定性与高可用设计

- **同步检测、毫秒级响应**：内置规则量级下，单次检测通常在数毫秒到数十毫秒，不引入外部服务调用。
- **无单点依赖**：规则与配置存于本地 SQLite，不依赖第三方审核 API；即使外部模型不可用也不影响主流程。
- **异常降级**：规则读取失败回退内置规则；检测抛错时返回 `error` 并转人工复核，不自动放行。
- **日志写入隔离**：日志写入失败只记录服务端错误，不影响资料提交本身。
- **阈值双保险**：单条强规则直接拦截 + 多规则累计分数升级，降低漏判与误判。
- **可回滚**：规则可随时停用；阈值可动态恢复；所有变更均有审计日志。

生产环境可在此基础上增加：规则灰度发布、模型打分服务、人工复核 SLA 告警、审计日志异地归档。

## 六、管理接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/admin/audit/overview` | 今日检测、拦截、待复核、平均耗时、阈值与分类统计 |
| GET | `/api/admin/audit/rules` | 规则列表（含分类与等级字典） |
| POST | `/api/admin/audit/rules` | 新增规则，即时生效 |
| PATCH | `/api/admin/audit/rules/:id` | 修改 / 启用 / 停用规则 |
| DELETE | `/api/admin/audit/rules/:id` | 删除规则 |
| POST | `/api/admin/audit/rules/test` | 文本试检测，不写日志 |
| POST | `/api/admin/audit/rules/reload` | 刷新规则缓存 |
| GET | `/api/admin/audit/logs` | 审核日志（`verdict` / `status` / `targetId` / 分页） |
| GET / PATCH | `/api/admin/audit/settings` | 读取 / 更新审核开关与分级阈值 |

以上接口均要求管理员身份。

## 七、验证

```bash
npm start
npm run test:audit   # 30 项：拦截、放行、转复核、日志、规则热更新、阈值、人工回写
```

测试会创建并清理临时资料，不会污染演示数据；拦截用例的内容不会入库，也不会留下上传文件。
