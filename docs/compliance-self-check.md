# 合规性自检报告 · v1.1.0

自检对象：学涯集市 · 高校学习资料交易平台
自检日期：2026-11-20
自检范围：代码实现、数据流程、交易链路、内容审核、权限与日志
自检性质：技术自检，不构成法律意见；外部资质与法律文本需由专业机构复核

---

## 一、总体结论

| 结论项 | 结果 |
| --- | --- |
| 代码级安全与隐私控制 | 已达到内测/测试环境要求 |
| 核心交易与资金链路 | 达到内测要求；真实资金需商户资质与联调 |
| 内容审核与学术合规 | 技术措施已具备，规则库需按实际运营持续维护 |
| 公网公测 | **条件性通过**：需完成 ICP 备案、公安联网备案、隐私政策/用户协议上线、账号注销机制、等保评估（或等保备案） |
| 当前是否可直接进入测试 | **是**（内测/预发环境） |
| 当前是否可直接面向全量公众收费 | **否**，外部资质与真实支付未完成 |

一句话：**技术红线已关闭，组织与外部资质红线仍需在上线前完成。**

## 二、法律法规对照

| 法律法规 / 标准 | 关键要求 | 当前状态 | 证据与差距 |

| 《著作权法》 / 《信息网络传播权保护条例》 | 授权链条、通知删除、侵权处理 | 部分落实 | 上传须承诺原创/授权，有举报与下架；需建立版权投诉与复核台账 |
| 教育部学术规范 / 学位论文作假处理办法 | 不得代写、买卖论文；范文仅作方法参考 | 已落实（技术层） | 论文类目合规定位、内容审核规则、人工复核、举报下架；见 `docs/thesis-compliance.md` |
| 《未成年人保护法》 | 年龄提示、监护人同意、防沉迷 | 未落实 | 当前无年龄门槛与未成年人模式，公测前需增加提示或限制 |
| 《生成式人工智能服务管理暂行办法》 | 内容标识、安全评估、算法备案 | 部分落实 | AI 客服与规划均为本地规则引擎，不调用外部大模型；需在页面标注「AI 生成/辅助」并保留人工兜底 |
| 《非银行支付机构监督管理条例》 | 不得无证从事支付业务、资金不得沉淀 | 已落实（技术层） | 平台不提供充值/提现，交易直达微信/支付宝/银行卡；真实收款需商户资质 |
| 《密码法》 | 商用密码合规 | 已落实（技术层） | 仅使用 Node 内置 scrypt/HMAC-SHA256，无自研密码算法 |
| ICP 备案 / 公安联网备案 | 境内公网服务备案 | 未完成 | 属于外部资质，需在上线前办理 |
| 网络安全等级保护 2.0 | 定级、备案、测评、整改 | 未完成 | 建议按二级定级；需第三方测评 |

## 六、审计与留痕

- 内容审核：规则命中、拦截、人工复核均写入审核日志，可在后台按分类与时间查询。
- 交易：订单、支付单、退款、结算形成完整链路，支持按订单号对账。
- 后台操作：当前覆盖审核、退款、改价、封禁等关键动作；建议补充统一管理员操作审计表。
- 用户侧：工单、举报、聊天记录保留，支持问题追溯。
- 请求侧：每个 API 请求带 requestId，可关联日志与用户。

## 七、自检结论

1. **代码与数据流程层面**：未发现可直接导致资金损失、越权访问、明文存储密码、伪造支付回调的高危问题；322 项测试覆盖核心链路。
2. **内测/预发环境**：满足进入测试环节的条件，无阻塞性代码问题。
3. **公测/收费环境**：需先关闭 R1—R4、R11，并完成等保与备案；这些属于组织与外部资质，不能由代码替代。
4. 本报告应随版本迭代更新；每次上线前由发布负责人、安全/合规、运营共同复核。
