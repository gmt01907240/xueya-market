# 多用户访问与局域网部署说明

本文说明如何让**多台电脑上的不同用户**同时访问并使用学涯集市。

## 1. 运行模式与架构

- 形态：B/S 架构 Web 应用，无需给使用者安装任何客户端软件。
- 一台电脑作为**服务端**（运行 Node.js 服务 + SQLite 数据库），其他电脑只用浏览器打开网址。
- 数据集中存放在服务端机器的 `data/` 目录（数据库 `xueya.db`、上传文件 `uploads/`），所有用户看到的是同一套数据，天然满足"注册、上架、购买、沟通、结算"需要多人共享数据的要求。
- 依赖网络：同一局域网即可，**不需要公网、不需要域名**。公网访问是可选项（见第 7 节）。
- 不建议每台电脑各自启动一份服务：那会得到互相独立的数据库，用户之间看不到彼此的数据。

## 2. 服务端准备（只做一次）

1. 安装 Node.js ≥ 22.5（`node -v` 确认）。
2. 进入项目目录，安装依赖：本项目零第三方依赖，直接启动即可。
3. 启动服务：

```bash
npm start
```

启动后终端会打印：

```
监听地址:  0.0.0.0:3300
本地地址:  http://localhost:3300
局域网地址（同一网络下的其他电脑用这些地址访问）:
           http://192.168.1.23:3300  (WLAN)
```

`0.0.0.0` 表示监听所有网络接口，**默认就允许其他电脑访问**，无需修改配置。终端只列出物理网卡的地址，VPN、虚拟机、加速器等虚拟网卡会被自动跳过。

### 可选环境变量

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `PORT` | `3300` | 监听端口，被占用时换一个（PowerShell：`$env:PORT=3301; npm start`；CMD：`set PORT=3301 && npm start`） |
| `HOST` | `0.0.0.0` | 监听地址。改成 `127.0.0.1` 会变成仅本机可访问 |
| `DATA_DIR` | `./data` | 数据目录，迁移机器时整体拷贝该目录即可 |
| `TRUST_PROXY` | 关闭 | 仅在前面有 Nginx 等反向代理时设为 `1` |

## 3. 客户端访问方式

其他电脑的浏览器直接打开服务端打印的**局域网地址**，例如 `http://192.168.1.23:3300`。

- 手机、平板连同一个 Wi-Fi 也能访问同一地址。
- 每个用户用自己的账号注册/登录，数据互不混淆，权限按角色区分（普通用户 / 卖家 / 管理员）。
- 浏览器建议 Chrome、Edge、Firefox、Safari 最近两个大版本。

## 4. 放行防火墙（其他电脑打不开时）

Windows 默认会拦截入站端口，需放行一次。**以管理员身份**打开 PowerShell，在项目目录执行：

```bash
npm run firewall:open
```

等价的手工命令：

```powershell
New-NetFirewallRule -DisplayName "学涯集市 TCP 3300" -Direction Inbound -Action Allow `
  -Protocol TCP -LocalPort 3300 -Profile Private, Domain
```

换端口时：`npm run firewall:open -- -Port 3301`（或修改脚本内的 `-Port` 参数）。撤销放行：`npm run firewall:open -- -Remove`。

注意：该规则只在「专用网络 / 域网络」生效。若 Windows 把当前网络识别为「公用网络」，请到「设置 → 网络和 Internet → 属性」改为「专用网络」。

## 5. 使用注意事项

- **不要关机 / 休眠服务端**：服务端机器休眠后所有用户都会断开；可在电源设置中关闭自动休眠。
- **服务端 IP 可能变化**：DHCP 重新分配后局域网地址会变，建议在路由器里给服务端机器绑定固定 IP，或每次启动时看终端打印的地址。
- **数据备份**：停止服务后整体复制 `data/` 目录即可（含数据库与上传文件）。建议每日备份一次。
- **重置数据**：`npm run reset` 会清空数据库与上传文件，仅在确认不需要保留数据时使用。
- **账号互通**：用户在任何一台电脑登录都是同一账号、同一数据；Token 有效期 7 天，服务端重启不影响已登录状态（签名密钥持久化在 `data/secret.key`）。
- **并发能力**：SQLite 已开启 WAL，适合班级、社团、几十人规模的内测；上百人同时在线时按 [deployment.md](./deployment.md) 迁移到 PostgreSQL 并配置反向代理。

## 6. 故障排查

| 现象 | 排查方向 |
| --- | --- |
| 本机能开，别的电脑打不开 | 防火墙未放行；网络位置是「公用网络」；两台电脑不在同一网段 |
| 地址能 ping 通但网页打不开 | 服务只监听了 `127.0.0.1`，检查是否设置了 `HOST`；端口被改过 |
| 打开是别的程序页面 | 端口冲突，换端口重启（PowerShell：`$env:PORT=3301; npm start`） |
| 校园网 / 公司网无法互访 | 网络开启了 AP 隔离或终端隔离，需联系网络管理员，或改用手机热点组网 |
| 手机能开首页但操作失败 | 检查服务端是否仍在运行；查看终端是否有报错日志（含 `requestId`） |

## 7. 公网访问（可选）

需要校外用户访问时，才涉及公网部署：

1. 路由器端口映射（WAN → 服务端内网 IP:3300），或使用云服务器；
2. 建议前置 Nginx 反向代理 + HTTPS 证书，并设置 `TRUST_PROXY=1`，否则限流会把代理 IP 当成所有用户的来源；
3. 生产环境设置 `NODE_ENV=production`、`SEED_DEMO=false`，并通过 `ADMIN_IP_ALLOWLIST` 限制后台入口；
4. 公网提供服务涉及 ICP 备案、公安备案、等保与真实支付商户资质，详见 [deployment.md](./deployment.md) 与 [compliance-self-check.md](./compliance-self-check.md)。

## 8. 快速自检

服务端启动后，在本机和其他电脑分别执行（或直接浏览器打开）：

```
http://<局域网IP>:3300/api/health
```

返回 `{"status":"ok","version":"1.1.0",...}` 即表示网络链路正常，可开始注册使用。
